You are an expert educational software developer. Your task is to architect a high-fidelity, interactive HTML5/JS simulation of a **Structural Engineering Studio**. 

### **CORE OBJECTIVE**
Create a web-based simulation where users interactively compare **Working Stress Method (WSM)** and **Limit State Method (LSM)**. The user must experience why LSM is the superior design philosophy through gamified structural testing.

---

### **1. AESTHETIC & UI ARCHITECTURE**
*   **Style**: Cyber-engineering dark dashboard. Use a deep charcoal background (#121212) with neon cyan, magenta, and lime-green accents. 
*   **Components**: Glassmorphic floating panels (backdrop-filter: blur) for text and controls. 
*   **Viewport**: Strict 100vh layout. No body scrollbars. Use CSS Grid to partition the screen:
    *   **Sidebar (Left)**: Interactive Checklist (Pending -> Completed state).
    *   **Canvas (Center)**: The main simulation stage (high-DPI, Retina-optimized).
    *   **Formula Drawer (Bottom)**: Active drag-and-drop slots for load/strength variables.
*   **Animations**: Fluid GSAP-powered transitions. Use "pulse" effects for steel rebars under load and "fading-in" stress block overlays on the RCC beam sections.

### **2. GAMIFIED SIMULATION LOGIC**
*   **The "Load-Test" Mechanism**:
    *   Display an RCC Beam cross-section on the canvas. 
    *   User drags "Weight Blocks" (Loads) onto the beam. 
    *   As weight is added, animate the **Neutral Axis** moving downward and the **Stress-Strain Block** (parabolic concrete/linear strain) updating in real-time.
    *   **Visual Feedback**: If the load exceeds design capacity, show a "CRITICAL FAILURE" glow (red pulse) and trigger a warning tone.
*   **Interactive Parameter Cards**:
    *   Display floating cards containing variables: `b` (width), `D` (depth), `fck` (concrete grade), `fy` (steel grade). 
    *   The user must drag these into the "Formula Slot" to "unlock" the capacity calculation equation.
*   **Comparative Mode (WSM vs LSM)**:
    *   Provide a toggle. When switched to **WSM**, show the section with a "Service Load" (low intensity). When switched to **LSM**, show the "Ultimate Load" (Load x Partial Safety Factor). 
    *   Visualize the "Efficiency Gap": Show a side-by-side bar chart showing that LSM utilizes material more effectively (lighter sections) vs WSM (heavier/uneconomical).

### **3. TECHNICAL SPECIFICATIONS**
*   **Engine**: Use HTML5 Canvas with the `requestAnimationFrame` loop for silky smooth vector rendering.
*   **Interaction**: Use `Interact.js` or standard HTML5 Drag-and-Drop API for the chips.
*   **Audio**:
    *   **Web Audio Synth**: Use a subtle 440Hz "Click" for card snaps and a low-frequency 60Hz "Thrum" for structural stress buildup.
    *   **Speech Synthesis**: Upon selecting a concept (e.g., "Partial Safety Factor"), the browser must narrate: *"Applying partial safety factors to account for material uncertainty and load variation."*
*   **Camera**: Implement a "Zoom & Pan" feature. When the user clicks the "Tension Zone," zoom the canvas 200% into that specific segment to highlight rebar placement/bonding.

### **4. PEDAGOGICAL CONTENT**
*   **Problem Statement**: "Why is Limit State Method more desirable than Working Stress Method?"
*   **Interactive Steps**:
    1.  **Identity Phase**: Identify variables in the section. Checklist item turns green when user clicks the correct components on the diagram.
    2.  **Safety Check**: Drag the "Safety Factor" chip into the calculation window to see the "Design Strength" update.
    3.  **Comparison**: Compare the "WSM Section Size" vs "LSM Section Size" as they generate on the canvas.
*   **Documentation Access**: Include a clickable "IS 456 Codebook" icon on the dashboard that, when opened, overlays a translucent snippet of the code (Clause 5.2.2.1) to guide the user.

### **5. RESTRICTIONS**
*   **NO EXAM PAPER CLUTTER**: Absolutely no simulated exam sheets, multiple-choice buttons, or static text boxes.
*   **Focus**: Purely on the 2D visual representation of structural physics, force vectors, and cross-sectional geometry.
*   **Performance**: Ensure responsive scaling to window resize events without distortion of the vector paths.

**Deliver the complete, single-file HTML/CSS/JS solution that embodies these requirements.**
