Act as a Senior Educational Software Architect and Lead Frontend Developer. Your objective is to build a high-fidelity, interactive, browser-based simulation module for Transportation Engineering, specifically focused on "Flexible vs. Rigid Pavement Classification."

### 1. Technical Framework & Aesthetic Requirements
*   **Layout**: Use a "Cyber-Engineering Dashboard" aesthetic. Implement a full-screen CSS Grid layout with a 100vh viewport constraint. No body overflow. 
*   **Visual Style**: Use a dark-mode theme with high-contrast neon accents (Cyan for structural lines, Magenta for pressure nodes, Lime for performance graphs). Use glass-morphism panels (backdrop-filter: blur) for UI overlays.
*   **Performance**: Use HTML5 Canvas with `requestAnimationFrame` for fluid animations. Ensure High-DPI (Retina) scaling by multiplying canvas CSS dimensions by `window.devicePixelRatio`.
*   **Soundscape**: Integrate the Web Audio API for interactive feedback:
    *   *Succesful Drop*: High-frequency resonant chime.
    *   *Incorrect Placement*: Low-frequency, muted thud.
    *   *Calculation Update*: Subtle, futuristic data-processing "whir" (oscillator sweep).
*   **Accessibility/Voice**: Use `window.speechSynthesis` to provide brief, professional narration when a student correctly places a parameter or completes a classification.

### 2. Core Interactive Simulation Blueprint
**Canvas Zones:**
*   **Split-Screen Sandbox**: Left side (Flexible Pavement cross-section) and Right side (Rigid Pavement cross-section).
*   **Parameter Bank**: A dock at the bottom containing "draggable cards" representing pavement properties (e.g., "High Elastic Modulus," "Load Distribution: Cone," "Temperature Stresses: Negligible," "Load Distribution: Wide Area," "Surface: Bituminous," "Surface: Concrete").

**Interaction Logic (Drag-and-Drop):**
*   Students must drag cards from the Bank onto the appropriate Pavement cross-section.
*   **Snap-to-Slot**: If a card is dropped on the correct Pavement type, the card glows green and snaps into a designated "Feature Slot." If incorrect, it snaps back to the bank with a "warning tone."
*   **Live Simulation Trigger**: Once all cards are placed, trigger a "Load Simulation." 
    *   *Rigid*: Animate a downward point load (vehicle tire) showing a wide pressure distribution cone and minimal structural deformation.
    *   *Flexible*: Animate the same load showing deep, layered compression and "trough-like" deflection curves (represented by animated vector lines).

### 3. Dynamic Engineering Overlays
*   **Force Vector Overlays**: Toggleable vector diagrams showing how vertical stress dissipates through the subgrade for each type. 
*   **Graphing**: Create a side-panel graph that updates in real-time as the simulation runs, plotting "Deflection vs. Load" for both pavement types to show the stark contrast in structural behavior.
*   **Zoom Tool**: Implement a "Micro-Inspector" mode where the cursor acts as a magnifying glass, showing the material layer transition (e.g., granular base vs. concrete slab) in 200% zoom.

### 4. Implementation Steps for the Model
1.  **Skeleton**: Build the `main.html` with a flexbox container. Create two primary `<canvas>` elements—one for each pavement type—and a `<div>` layer for DOM-based draggable UI cards.
2.  **State Management**: Implement a state object to track the "Pavement Integrity" status (Boolean flags for each correctly identified component).
3.  **Animation Engine**: 
    *   Write a function to draw the pavement layers (e.g., Subgrade, Sub-base, Base, Surface).
    *   Write an `animateLoad()` function that draws dynamic pressure distribution lines (curved for flexible, trapezoidal for rigid) upon a click event.
4.  **Audio/Voice Logic**: Integrate a `speak(text)` utility function to explain the difference in load-bearing mechanics the moment the simulation runs.
5.  **Responsiveness**: Ensure the canvas redraws on `resize` events to maintain visual fidelity, using `requestAnimationFrame` to prevent flicker.

### 5. Constraints
*   **NO TEXTBOOK BLOCKS**: Do not create generic "fill-in-the-blank" forms. The interaction must happen on the diagram itself.
*   **CODE QUALITY**: Write modular, clean, and well-commented vanilla JavaScript/ES6. Use CSS variables for the color palette to allow for easy theme adjustments.
*   **PEDAGOGY**: Ensure the narration reinforces *why* rigid pavements fail under temperature cycles compared to flexible pavements.
