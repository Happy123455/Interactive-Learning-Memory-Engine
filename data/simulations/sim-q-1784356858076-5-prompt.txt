**Role:** You are an expert Educational Software Engineer and Creative Technologist specializing in interactive physics simulations.

**Task:** Build a single-file, high-fidelity interactive simulation using HTML5, CSS3, and Vanilla JavaScript to explain "The Importance of Soil Behavior as a Highway Material" in Transportation Engineering.

**Project Vision:**
Create a "Soil Mechanics Laboratory Dashboard" that demonstrates how soil properties (load-bearing capacity, drainage, and plasticity) directly impact highway pavement longevity. The UI must feature a modern, dark-themed, glassmorphic design with neon accents.

### 1. Visual Simulation Strategy
*   **The Scene:** Implement a 2D Canvas-based cross-section of a highway structure (Subgrade soil, Sub-base, Base, Asphalt).
*   **The Simulation:** Use a requestAnimationFrame loop. When the user interacts, show a vertical cross-section of the road being compressed by a vehicle.
*   **Animations:** Use vector arrow overlays to represent "Stress Distribution" (pressure bulbs). As soil quality changes (via sliders), the color/length of these vectors should dynamically animate to show how stress spreads or concentrates.

### 2. Interactive Elements
*   **Drag-and-Drop:** Allow users to drag "Soil Samples" (e.g., Clay, Sand, Silt) onto the "Subgrade" zone.
*   **Control Panel (Glassmorphic):**
    *   **Sliders:** Modify "Moisture Content (%)" and "Compaction Effort."
    *   **Real-time Plotting:** Use Chart.js or a custom Canvas path to plot a "Stress vs. Settlement" graph that updates instantly based on soil type and load.
    *   **Info Box:** Display dynamic text calculating the "Bearing Capacity" (q_u) using basic soil mechanics formulas.

### 3. Web Audio API (Native Synthesis)
*   **Implementation:** Do not use external files. Use `AudioContext` with `OscillatorNodes` and `GainNodes`.
*   **Sounds:** 
    *   **Interaction:** A soft "click" (low-pass filtered sine wave) on button press.
    *   **Error/Warning:** A subtle "low-frequency hum" if the soil fails (shear failure) under the load.
    *   **Action:** A harmonic "sweep" when the simulation graph updates.

### 4. Narrative Text-to-Speech (TTS)
*   **Engine:** Integrate `window.speechSynthesis`.
*   **Features:** Include a "Narrate" button for each section. When clicked, the script should iterate through a structured JSON object containing explanations of the current state (e.g., "The soil is currently in a state of low compaction, leading to excessive settlement under traffic loads.")
*   **Automation:** Trigger brief explanations when a user drags a new soil type into the simulation.

### 5. Mathematical Aesthetics & UI
*   **Aesthetics:** Dark charcoal background (`#0a0a0a`), glowing cyan (`#00d4ff`) and magenta (`#ff007a`) neon accents.
*   **Typography:** Use Inter or Roboto (sans-serif).
*   **Math Rendering:** Use LaTeX-style formatting for equations (e.g., $q_u = cN_c + qN_q + 0.5\gamma BN_\gamma$) rendered in a glassmorphic container that scales smoothly.
*   **Transitions:** Use CSS `transition: all 0.3s ease-in-out` for all interactive elements to ensure a premium feel.

### 6. Technical Requirements
*   Single HTML file structure: CSS in `<style>`, JS in `<script>`.
*   Responsive layout: Ensure the dashboard elements are collapsible on smaller screens.
*   Error Handling: Ensure `speechSynthesis` does not crash if the browser blocks auto-play audio (handle with a user-gesture requirement).

**Instruction to the Developer:**
*   Start with the Canvas setup.
*   Build the interaction logic for drag-and-drop.
*   Implement the mathematical graphing function that updates the visual stress vectors.
*   Layer the Web Audio API feedback for a tactile user experience.
*   Finalize with the TTS narration integration for accessibility and deep learning.
