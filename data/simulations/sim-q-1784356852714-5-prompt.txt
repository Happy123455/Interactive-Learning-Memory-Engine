# Instruction Prompt for Gemini: Interactive Transportation Engineering Simulator

**Role**: Act as a Senior Educational Developer and Lead Simulation Architect specializing in interactive STEM visualization.

**Objective**: Build a high-fidelity, gamified, browser-based simulation for "Horizontal Alignment Widening" in Transportation Engineering. The simulation must be an interactive "Physics Sandbox" where students manipulate road parameters to observe mechanical and safety responses in real-time.

---

### 1. Visual & Aesthetic Architecture (The "Cyber-Engineering" Dashboard)
- **Interface**: Implement a "Glassmorphism" UI—translucent dark containers, neon cyan/purple/green glow accents, and a clean, high-contrast grid-based workspace.
- **Canvas/Layout**: Use a `100vh` flex/grid layout. No scrollbars allowed. The canvas must support high-DPI rendering (canvas scaling) and resize dynamically.
- **Style**: Professional "Engineering Command Center" aesthetic with smooth CSS transitions for UI elements.

### 2. Gamified Interactive Mechanics
- **The "Problem Card"**: A floating, draggable panel containing the problem text: *"Calculate the extra width of pavement required on a horizontal curve of radius 700 m on a two-lane highway, design speed 80 kmph. Wheel base = 6 m."*
- **Interactive Variables**: The variables (R=700, V=80, L=6) must be highlightable chips that can be dragged and dropped into their respective slots in the interactive formula interface.
- **Canvas Interaction**: 
    - **Dynamic Curve**: An HTML5 Canvas drawing of a road segment. As the user changes R (radius), the curve visual radius must update in real-time via `requestAnimationFrame`.
    - **Gesture Control**: Allow mouse/pointer dragging across the curve to "sweep" the road and view perspective shifts, mimicking hand-motion gesture control.

### 3. Engineering Simulation Components
- **Formula Slot Engine**: When values (R, V, L) are dragged into the formula: $W_e = W_{ps} + W_m = \frac{nl^2}{2R} + \frac{9.6 \sqrt{R}}{\sqrt{R}}$ (where applicable), the system must validate the input with a green/red "snap-in" ring animation.
- **Physics Visualizer**: Display real-time force vectors (Centrifugal Force $P$) as glowing arrows pulling the vehicle outward. Moving the speed slider must dynamically change the arrow length and the pitch of a Web Audio Oscillator (higher speed = higher frequency "squeak").
- **Dynamic Graphs**: A sidebar graph plotting "Extra Widening vs. Radius" that updates live as the user slides the radius parameter.

### 4. Active Pedagogy & ELI5 Sandbox
- **Narrator**: Use `window.speechSynthesis` to provide friendly narration. When the user successfully drops a chip, the agent should say: *"Great job! By tightening the curve, we are making the road safer for cars to turn!"*
- **ELI5 Analogies**: Include a "Toy Mode" toggle that explains the concept: "Think of the road as a tight rubber band; when we curve it, the cars need a little extra room to stretch, just like you need extra space to run around a sharp corner!"
- **Sound Design**:
    - **Success**: A light chime/bouncy "Ding" when values snap into formulas.
    - **Feedback**: A deep, low-frequency "thrum" when the vehicle simulation hits physical limits.
    - **Oscillator**: Link the centrifugal force vector length to an oscillator pitch.

### 5. Technical Requirements for Implementation
- **Clean Architecture**: Use ES6 modules. No external bulky physics libraries; write custom coordinate-based kinematics for the vehicle pathing.
- **Step-by-Step Checklist**: A status side-panel that moves from "Pending" to "Calculated" as the student completes the steps:
    1. Identify Variables.
    2. Calculate Mechanical Widening ($W_{ps}$).
    3. Calculate Psychological Widening ($W_{m}$).
    4. Determine Total Extra Width.
- **Zoom/Focus**: When calculating $W_{ps}$, trigger an automatic HTML5 Canvas zoom-in on the "Inner Curve" area to show the "Off-tracking" effect of the rear wheels vs. the front wheels.

### 6. Critical Constraints
- **NO Exam Paper Clutter**: Do not draw images of exam sheets, paper, or text boxes that look like tests. Everything must feel like a live, interactive, futuristic engineering tool.
- **Zero Scrollbars**: Enforce strict CSS overflow hidden/auto rules to ensure a single-screen, immersive application.
- **Responsiveness**: Ensure the canvas redraws smoothly on window resize events to maintain aspect ratio for the road alignment visualization.

---

**Execution**: Provide the full HTML/CSS/JS code block. Ensure the Javascript includes logic to calculate the Mechanical and Psychological widening based on the provided inputs and display the result as a dynamic, glowing value on the canvas.
