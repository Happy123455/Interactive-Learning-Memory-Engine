**PROMPT FOR CODE GENERATOR:**

**Role:** Act as a Senior Educational Software Architect and Lead Frontend Engineer. You are tasked with creating a "Universal Gamified Engineering Studio"—a single-file, production-ready HTML/JS application (using Canvas API, Tailwind CSS, and Web Audio API) to simulate the design of an RCC Column.

**Objective:** Build a high-fidelity, interactive simulation for the problem: "A short R.C.C. column of size b x d mm carries a 1500kN axial load. Design the column. Grade: M25. Unsupported length: 3m." 

### 1. UX/UI & Environment Architecture
*   **The Studio:** Use a "Dark Engineering Studio" theme. Background: `#0f172a`. Panels: `#1e293b` with border-color `#334155`. 
*   **3-Panel Layout:**
    *   **Left (Control Panel):** Interactive checklist of variables ($b, d, P, fck, L$). As variables are clicked in the problem statement, they trigger animation steps in the canvas.
    *   **Center (Simulation Canvas):** The primary workspace. Use HTML5 Canvas to render a dynamic RCC column cross-section. Implement zoom-in capabilities (150% scale) for specific reinforcement zones.
    *   **Right (Codebook & Logic):** A scrollable "IS 456 Codebook" panel. Users must drag specific clauses or charts onto the "Formula Assembly" zone in the center.

### 2. Gamified Engineering Mechanics (The 6-Step Loop)
*   **Data Extraction:** When the user clicks values in the problem text, render the column outline on the Canvas. Animate "Growth" lines for width ($b$) and depth ($d$). 
*   **Codebook Lookup:** Create a draggable mini-book UI. The user must find the "Axial Load Column" clause. When dropped into the slot, it unlocks the formula $P_u = 0.4 f_{ck} A_c + 0.67 f_y A_{sc}$.
*   **Drag-and-Drop Formula Assembly:** Provide numerical "Value Chips" (e.g., "1500", "0.25", "M25") at the bottom of the screen. Users must drag chips into correct formula placeholders. 
    *   *Feedback:* Correct snaps trigger a pleasant "Chime" (Web Audio Synth) and a green border glow. Incorrect chips vibrate and trigger a "Warning Tone."
*   **Stress-Strain Visualization:** Upon successful calculation, overlay a dynamic stress-strain diagram next to the column. The parabolic concrete stress profile should scale in real-time as $f_{ck}$ is adjusted.

### 3. Visual & Technical Requirements
*   **Animations:** 
    *   **Pour Effect:** When concrete grade (M25) is confirmed, fill the column cross-section on the canvas with a fluid, liquid-concrete animation.
    *   **Glowing Rebar:** Once steel reinforcement ($A_{sc}$) is calculated, render neon-glowing steel rods inside the concrete section.
*   **Camera Work:** Implement a smooth `ctx.scale()` transformation when transitioning from "Global View" to "Cross-Section Detail." Focus the camera specifically on the rebar-concrete interface with a red pulsating highlight.
*   **Audio & Narration:**
    *   Use `window.speechSynthesis` to provide brief, professional narration when a student successfully completes a design step (e.g., "Compression capacity verified").
    *   Synthesize clean, high-frequency beeps for UI interactions and a soft "thud" for snap-drops.

### 4. Code Structure Constraints
*   **NO CLUTTER:** Zero text-box exam layouts. Every element must be a physical, draggable, or clickable object within the canvas.
*   **State Management:** Create a `simulationState` object to track the flow (Step 1-6). Only allow the next step when the current one is validated.
*   **Styling:** Use Tailwind CSS classes for high-end glassmorphism. Ensure all labels have white/neon text against the dark backdrop.

### 5. Interaction Execution
*   **Vector Overlays:** Display the 1500kN axial force as a bold, downward-pointing vector arrow centered on the column. As design parameters change, animate the arrow's color (Red if failing/under-reinforced, Green if safe).
*   **Checklist:** A dynamically updating "Pending/Identified" checklist that triggers an "Unlock" sound effect when the design phase is completed.

**Deliverable:** A single-file HTML/JS/CSS code block. Do not use external libraries; rely on native Canvas API and CSS variables. Start the code with a clear initialization function and maintain modular, readable functions for the animation loop.
