**System Role:** You are an expert educational software engineer specializing in interactive simulations for Civil and Transportation Engineering. Your task is to build a single-file HTML/JS simulation (HTML5, CSS3, ES6) that teaches the "Desirable Properties of Aggregates in Road Construction."

**Objective:** Create a highly interactive, aesthetic, and pedagogical tool that allows students to manipulate aggregate properties (Hardness, Toughness, Shape, Surface Texture) and observe their real-time impact on pavement performance metrics.

### 1. Visual Simulation Strategy
*   **Core Visualization:** Use a `<canvas>` element for a high-performance 2D physics loop.
*   **The Scenario:** Create a "Virtual Pavement Stress Test" animation. Display a rolling wheel over a cross-section of pavement.
*   **Dynamic Objects:** The pavement layer should be represented by particle clusters (aggregates). As the wheel moves, color-code these aggregates based on the "Property" currently being tested (e.g., green for high durability, red for poor structural integrity).

### 2. Interactive Dashboard
*   **Controls:** Create a glassmorphic sidebar with range sliders for:
    *   *Hardness (Mohs Scale):* Affects deformation.
    *   *Toughness (Impact Resistance):* Affects fracture animation.
    *   *Angular/Rounded Shape:* Affects interlocking force vectors.
    *   *Surface Texture:* Affects friction coefficients.
*   **Physics Interaction:** Implement a "Drag and Drop" feature. Allow the user to drag specific aggregates into a "Crush Test" zone. When dropped, trigger a stress simulation showing force vectors (arrows) radiating from the contact point.

### 3. Diagram & Graphing Overlays
*   **Live Plotting:** Use a chart overlay (Canvas-based) that updates in real-time as users move sliders. Show a "Performance vs. Property" curve that shifts dynamically.
*   **Vector Overlays:** Display animated force arrows around the aggregate particles. When the user increases "Angular shape," show overlapping vector icons indicating higher interlock friction.
*   **Equation Rendering:** Display the math behind the stress, e.g., $\sigma = F/A$, with the variables updating instantly based on slider input.

### 4. Audio Design (Web Audio API Only)
*   **Impact Sounds:** On "Crush Test" events, use the `WebAudio API` to generate a percussive click/thud using an oscillator (low frequency) + gain node (exponential ramp for envelope).
*   **Status Tones:** Generate a soft sine-wave beep (low pass filter) when values reach the "Optimal" range for road construction.
*   **No external assets:** All sounds must be synthesized via `new AudioContext()`.

### 5. Educational Narration (Speech Synthesis)
*   **Narrate Button:** Include a "Narrate Concept" button.
*   **Functionality:** Use `window.speechSynthesis`. When triggered, it must explain the currently selected property (e.g., "Increasing aggregate toughness reduces the likelihood of crushing under heavy wheel loads").
*   **Auto-Trigger:** Provide an option for the app to narrate the "Why" behind a score update when a user drags and drops a new aggregate sample.

### 6. Aesthetics & UI/UX
*   **Theme:** Dark mode aesthetic. Background: `#0f172a` (Deep Navy). 
*   **Accents:** Use neon cyan (`#22d3ee`) for active vectors and glowing white for text.
*   **Glassmorphism:** Control panels must use `backdrop-filter: blur(10px)` with semi-transparent dark backgrounds.
*   **Typography:** Clean sans-serif fonts (e.g., Inter or Roboto) with high contrast.
*   **Transitions:** Use CSS `transition: all 0.3s ease-in-out` for all property changes and UI movements.

### 7. Technical Requirements
*   **Single File:** All CSS, JS, and HTML must be within one file.
*   **Structure:**
    *   `init()` function to set up the canvas and audio context.
    *   `render()` loop for animations.
    *   `updatePhysics()` function to modify aggregate behavior based on UI sliders.
    *   `handleDrop()` event listener for drag-and-drop aggregate testing.
*   **Safety:** Ensure the simulation is responsive and accessible.

**Constraint:** The code must be clean, commented, and follow modern ES6+ practices. Provide the complete code in a single code block.
