**Role:** You are an expert Educational Software Engineer and Web Developer specializing in high-fidelity interactive physics simulations. 

**Task:** Create a single-file (HTML/CSS/JS) interactive web simulation for an "Elementary Structural Design" course, specifically visualizing the failure modes of Singly Reinforced Concrete Beams (Under-reinforced vs. Over-reinforced).

**1. Visual Simulation Strategy:**
*   Use an HTML5 `<canvas>` for the rendering engine.
*   **The Beam:** Represent a rectangular RCC beam cross-section. Draw the concrete zone in a muted grey and the steel reinforcement bars as circles at the bottom.
*   **Stress Block:** Overlay a translucent orange "Stress Block" (Whitney Stress Block) above the neutral axis.
*   **Physics Loop:** Implement a requestAnimationFrame loop. As the user adjusts the steel area ($A_{st}$) via a slider, dynamically update the depth of the neutral axis ($x_u$) and the internal lever arm based on limit state equations.
*   **Vector Overlays:** Draw real-time vectors representing Compression ($C$) and Tension ($T$) forces. These arrows must scale in length and animate smoothly based on the calculation of $0.36 f_{ck} b x_u$ and $0.87 f_y A_{st}$.

**2. Interactive Elements:**
*   **Steel Slider:** A slider to adjust the Area of Steel ($A_{st}$). Moving this slider must transition the beam state from "Under-Reinforced" (fail by steel yielding) to "Balanced" to "Over-Reinforced" (fail by concrete crushing).
*   **Drag & Drop:** Allow the user to drag a "Load Application" handle on the beam. As the load increases, animate the strain distribution diagram on a side panel.
*   **Mode Switcher:** Toggle buttons to snap the beam into specific pre-set configurations (Under, Balanced, Over).

**3. Sound Design (Web Audio API):**
*   Implement a `SoundEngine` class using `AudioContext`.
*   **Failure Cue:** Trigger a low-frequency oscillator sweep (100Hz down to 20Hz) with a distortion gain node to simulate "cracking/crushing" when the failure mode limit is reached.
*   **Interaction Feedback:** Generate a soft, high-frequency "pluck" (sine wave, short decay) when sliders are moved or values update.
*   **Mode Change:** Trigger a resonant beep (440Hz for Under, 880Hz for Over) when the state shifts.

**4. Narrative Text-to-Speech (TTS):**
*   Include a "Narrate Concept" button. 
*   Use `window.speechSynthesis` to provide audio cues. When the simulation enters the "Over-Reinforced" state, the narration should automatically trigger: "Warning: Over-reinforced section. The concrete reaches its ultimate strain before the steel yields, leading to brittle failure."
*   Provide a queue system so TTS doesn't overlap with sound effects.

**5. Real-Time Math & Diagrams:**
*   **Equation Rendering:** Use a fixed overlay text area that displays live values: $x_u$ (Neutral axis depth), $M_u$ (Moment capacity), and $C/T$ force values.
*   **Strain Diagram:** A secondary 2D canvas displaying the strain triangle, which updates linearly based on the Neutral Axis depth. Animate the strain line color: Green (safe), Yellow (yielding), Red (crushing).

**6. Aesthetics & UI/UX:**
*   **Theme:** Dark mode aesthetic. Background: `#0f172a`.
*   **Glassmorphism:** Use `backdrop-filter: blur(10px)` with semi-transparent white/blue backgrounds for control panels.
*   **Typography:** Sans-serif (e.g., 'Inter' or 'Roboto').
*   **Neon Accents:** Use glowing borders (box-shadow) on active components: cyan for steel reinforcement, magenta for the stress block, and lime for the neutral axis line.
*   **Responsiveness:** Ensure the canvas occupies the center of the viewport, with controls docked in a clean, floating side-panel.

**Technical Requirements:**
*   Vanilla JavaScript only (no external frameworks).
*   Responsive layout that fits desktop/tablet browsers.
*   Include robust comments explaining the structural logic (Limit State Design principles).
*   Ensure smooth transitions for all vector scaling.
