Act as an expert Educational Software Engineer. Your task is to develop a single-file, high-performance HTML/CSS/JS simulation for "Design of Singly Reinforced RCC Beams (Limit State Method)." The goal is to create an interactive pedagogical tool that allows students to manipulate beam parameters and visualize the resulting stress-strain distribution in real-time.

### 1. Visual Simulation Strategy
*   **Main Workspace:** Use an HTML5 `<canvas>` element for a high-fidelity 2D structural diagram.
*   **Beam Representation:** Draw a cross-sectional view of the beam. Dynamically scale the depth (D) and width (b) based on user input.
*   **Stress-Strain Plot:** Overlay a secondary canvas plotting the Parabolic-Rectangular stress block (as per IS 456:2000 standards).
*   **Physics Loop:** Use `requestAnimationFrame` to animate the transition between different beam states (e.g., from balanced to under-reinforced) when inputs change.

### 2. Interactive Elements
*   **Draggable Handles:** Implement draggable points on the beam cross-section to visually resize the concrete area (b, d).
*   **Control Panel:** A glassmorphic side-panel containing:
    *   `<input type="range">` sliders for: Concrete Grade (fck), Steel Grade (fy), Span Length, and Load (w).
    *   Interactive numeric readouts that update as sliders move.
*   **Real-time Math:** Use `MathJax` or custom text-rendering on the canvas to display:
    *   `Mu_lim = 0.138 * fck * b * d^2` (or current calculation).
    *   Live calculation of Neutral Axis depth (xu) vs. Limiting Depth (xu_lim).

### 3. Web Audio API Sound Design
Implement a `SoundEngine` class using `AudioContext`:
*   **Parameter Change:** A subtle, low-frequency sine-wave "thrum" (50Hz) that sweeps upward in pitch when slider values increase.
*   **Safety Threshold:** If the beam becomes "Over-Reinforced" (xu > xu_lim), trigger a low-pass filtered sawtooth pulse to indicate a non-ductile failure warning.
*   **Interaction:** A crisp "click" sound (short white noise burst with exponential decay) on button presses.

### 4. Narrative Text-to-Speech
*   Integrate `window.speechSynthesis`.
*   Include a "Narrator" toggle. When enabled, the model should trigger speech synthesis to explain the current state (e.g., "The neutral axis has shifted; the beam is now under-reinforced, promoting ductile failure").
*   Contextual Help: Add a "Guide Me" button that iterates through the design steps, narrating the purpose of each variable.

### 5. Diagram Animations & Aesthetics
*   **Theme:** Dark mode aesthetic (background `#0f172a`).
*   **Accents:** Glowing neon borders (`#22d3ee` for labels, `#f472b6` for stress block vectors).
*   **Animations:** 
    *   Use `GSAP` or simple linear interpolation (LERP) for smooth transitions of all visual elements when parameters change.
    *   Vectors (arrows) representing compression and tension forces must resize dynamically to reflect the internal couple calculation.

### 6. Technical Requirements
*   **Self-Contained:** All CSS and JS must be embedded within a single `.html` file.
*   **Structure:**
    *   `AppState`: A central object holding current beam dimensions and material properties.
    *   `RenderEngine`: Functions for drawing the beam, the stress block, and updating vector lengths.
    *   `InteractionHandler`: Mouse/Touch event listeners for the draggable handles.
    *   `Calculator`: Functions to compute structural capacity dynamically.
*   **Responsive:** Ensure the canvas resizes to fit the viewport while maintaining a clear view of the beam and the stress-strain plots.

**Goal:** Create a tool where the student feels the "weight" of the beam design through visual feedback, sonic cues, and immediate mathematical reality. Ensure the code is clean, commented, and highly modular.
