You are an expert educational software engineer. Your task is to generate a high-performance, single-file HTML/JavaScript simulation for a Transportation Engineering module.

### **Core Simulation Objective**
Build an interactive **Horizontal Transition Curve Designer**. The user must calculate the length of a horizontal transition curve using the provided input data:
*   **Pavement width (w)** = 7.0 m
*   **Rate of introduction of superelevation (N)** = 1 in 150
*   **Rotation** = About inner edge
*   **Extra widening (We)** = 0.45 m
*   **Design Speed (v)** = 90 Kmph
*   **Radius (R)** = 350 m

### **1. Visual & Aesthetic Architecture**
*   **Dark Mode Dashboard**: Use a "Cyber-Engineering" aesthetic: deep slate-grey backgrounds, translucent "frosted glass" panels, and vibrant neon accents (Cyan for measurements, Magenta for forces, Lime Green for correct answers).
*   **Layout**: Use a CSS Grid/Flexbox layout with `100vh` containment. No body scrolling. The simulation space should be responsive, utilizing `requestAnimationFrame` for fluid animations.
*   **Canvas Elements**: Use an HTML5 Canvas for the engineering drawing. It must support high-DPI (Retina) scaling and show a top-down view of a highway curve.

### **2. Interaction Mechanics**
*   **Playful ELI5 Sandbox**: Integrate a "Helpful Robot" persona. When a user hovers over a component, `window.speechSynthesis` should narrate the engineering concept in a friendly, simplified tone (e.g., "Imagine the car is a playful puppy running around a corner, we need to make sure it doesn't slide off!").
*   **Advanced Drag & Drop**:
    *   Create a "Component Tray" containing numerical chips, parameter icons (speed, radius, width), and physical markers.
    *   Users drag these into the **"Active Formula Slot"** on the canvas. When a chip enters a slot, trigger a "snap" effect, a satisfying chime, and a green pulse glow.
*   **Hand Motion Gesture Control**: Use the Mouse/Pointer API to allow users to "sweep" the screen to change the curve radius or speed, watching the force vectors (centrifugal vs. friction) shift in real-time.

### **3. Engineering Simulation Features (RCC/Transport Style)**
*   **Dynamic Drafting**: As the user drags the "Radius" slider, animate the transition curve growth on the canvas using bezier curves.
*   **Force Vector Visualizer**: Show glowing arrows representing Centrifugal Force (P) and Friction. As the user adjusts parameters, the arrows should scale and pulse (longer = more dangerous).
*   **Pitch-Shifting Feedback**: Connect the Web Audio API to the input sliders. Increasing "Design Speed" or "Radius" should modulate the pitch of a background oscillator (higher speed = higher frequency, lower = bassy rumble).
*   **Formula Solver**: Implement an interactive step-by-step solver. Users must drag correct constants from the "Codebook" (clickable IRC 456-style overlay) to the equation to unlock the next calculation step.

### **4. Required Code Structure**
*   **No Clutter**: Do not include boilerplate text boxes. Every element must be a functioning UI component.
*   **State Management**: Create a `SimulationState` object to track user progress (e.g., `identifiedVariables`, `equationStep`, `isSolved`).
*   **Visual Transitions**: Use GSAP or CSS Keyframes for smooth transitions between the "Problem Identification" phase (checking off variables) and the "Drafting" phase.
*   **Responsive Canvas**: Ensure the canvas redraws on `window.resize`. Include a "Zoom/Pan" feature where users can click the curve to perform a 150% zoom into the transition segment.

### **5. Implementation Guidelines**
*   **Physics Logic**: Use standard transportation engineering formulas ($L_s = \frac{v^3}{CR}$ and $L_s = \frac{eN(W+W_e)}{2}$) to drive the simulation.
*   **Visual Feedback**: If a student inputs a value that causes a "skid," trigger a warning tone, highlight the pavement in pulsing red, and provide a pop-up with a "Gummy Bear" analogy for the failure.
*   **Code Quality**: Use modern ES6+ JavaScript, modular functions for rendering, and strict CSS variables for the color palette to ensure a "premium engineering software" look.
