**PROMPT FOR CODE GENERATOR (GEMINI)**

**ROLE:** Expert Educational Software Developer & Structural Engineering Simulation Architect.
**TASK:** Develop a high-fidelity, single-file HTML5/JS/CSS interactive simulation for "Rigid Pavement Design Factors."

### 1. CORE ARCHITECTURAL REQUIREMENTS
*   **Single-File Architecture**: All CSS, JavaScript, and HTML must be contained in one file.
*   **Viewport Management**: Use `100vh` and `100vw` container constraints. No scrollbars allowed. Use `flex` or `grid` for a responsive, dashboard-style interface.
*   **Aesthetic Profile**: Cyber-engineering dashboard. Dark glassmorphism panels, neon cyan/purple accents, high-contrast white text, and fluid GSAP-style transitions.
*   **Visual Strategy**: High-DPI Retina-ready `<canvas>` for all vector diagrams. 

### 2. GAMIFIED SIMULATION SCENARIO: "The Pavement Stress Lab"
Instead of text, create a sandbox where the user acts as a Materials Engineer.
*   **The Canvas**: A cross-section of a rigid pavement structure (Subgrade, Sub-base, Concrete Slab) with interactive layers.
*   **The Interaction**: Drag-and-drop "Factor Cards" (e.g., "Wheel Load," "Temperature Gradient," "Subgrade Support," "Traffic Volume") from a sidebar into the pavement diagram.
*   **Live Feedback**: Upon dropping a card, trigger a visual reaction:
    *   *Wheel Load*: Create a force vector arrow (animated) pressing on the slab, showing deformation/deflection.
    *   *Temperature*: Change the slab geometry (curling/warping) with a heatmap overlay (Red for high-stress zones).
    *   *Subgrade*: Toggle the stiffness of the foundation layer beneath the slab.
*   **Real-time Graphing**: As factors are added, a real-time side-panel graph must update to show the "Total Stress Intensity" (Westergaard’s stress distribution).

### 3. TECHNICAL SPECIFICATIONS
*   **Drag & Drop**: Implement standard HTML5 Drag-and-Drop API or interact.js-style movement. Include "Snap-to-Slot" functionality with a satisfying "chime" sound (Web Audio API) when a factor is correctly placed.
*   **Speech & Audio**: 
    *   `window.speechSynthesis` must narrate the engineering implication of a factor once dropped (e.g., "Temperature gradient creates upward curling stress at the slab edges").
    *   Use `AudioContext` to generate subtle UI clicks, successful drag-snaps, and warning tones if variables are set to extreme (unsafe) values.
*   **Formula/Calculation Linkage**: Provide a "Reference Drawer" (IS Codebook Style) which the user clicks to pull up relevant design equations. Integrate "Slot Puzzle" mechanics: the user must drag numerical variables from the diagram into these formula fields to compute the output.

### 4. DYNAMIC UI COMPONENTS
*   **Vector Overlays**: Use `requestAnimationFrame` to draw smooth, pulsing force vectors and stress lines.
*   **Interactive Annotations**: Use `z-index` layering to ensure that annotations on the canvas are readable, with a semi-transparent black background behind text to prevent readability issues.
*   **Camera Zooming**: Implement a zoom/pan feature using `ctx.scale()` and `ctx.translate()` to allow users to zoom into the "Critical Stress Zone" (the corner/edge of the pavement) when analyzing curling stresses.

### 5. PEDAGOGICAL FLOW
1.  **Phase 1: Identification**: User is presented with a "Pending" checklist of pavement factors. 
2.  **Phase 2: Simulation**: User drags cards to the diagram. Each card updates the visual model (e.g., slab deformation, color-coded stress gradients).
3.  **Phase 3: Validation**: A "Calculate Stress" button appears only when all critical factors are placed. Clicking it triggers a calculation animation showing the result on a dynamic bar chart.

### 6. CODING CONSTRAINTS
*   **NO CLUTTER**: Absolutely no textbook-style block text. Every piece of information must be embedded in an interactive element or a toggleable tooltip.
*   **Clean Code**: Modular JavaScript (ES6+). Use clear variable naming conventions.
*   **Accessibility**: High-contrast, scalable text; ARIA labels for canvas regions.

**BUILD INSTRUCTIONS:** Start by rendering the dark dashboard layout, then construct the canvas engine. Initialize the "Factor Cards" as draggable objects. Ensure the voice synthesis triggers upon the `drop` event of each card. Finalize with the equation-solving logic that updates the canvas plots.
