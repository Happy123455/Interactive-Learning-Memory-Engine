Act as a Senior Frontend Lead and Educational Systems Architect. Your objective is to build a high-fidelity, gamified web-based simulation for "Transportation Engineering: Design of Flexible Pavements."

### 1. OVERALL ARCHITECTURAL MANDATE
- **Layout**: Utilize a 100vh CSS Grid layout. Left panel: 30% width "Mission Control" (problem text, parameter checklist, and interactive book). Center panel: 70% width "Simulation Studio" (HTML5 Canvas).
- **Theme**: "Cyber-Engineering Dark Mode"—Deep obsidian backgrounds, frosted glass (backdrop-filter: blur) panels, cyan neon text for variables, and amber alerts for stress warnings.
- **Responsiveness**: Use ResizeObserver to ensure the Canvas maintains internal coordinate stability across all resolutions.

### 2. CORE SIMULATION COMPONENTS
- **Interactive Problem Statement**: Render the question ("Explain factors for flexible pavement design") as an interactive checklist. As the user identifies a factor (Traffic, Subgrade, Environment, Materials), they click it, and it glows; the "Mission Control" panel updates the status from *PENDING* to *ANALYZED*.
- **The "Pavement Lab" Canvas**:
    - Build a 2D cross-section layering simulation (Subgrade, Sub-base, Base, Surface).
    - **Draggable Parameters**: Create a set of "Factor Chips" (e.g., 'High Traffic', 'Heavy Rainfall', 'Expansive Soil', 'Temperature Variance'). 
    - **Drag-and-Drop Slots**: The canvas must contain drop targets on the road layers. Dropping a 'Heavy Rainfall' chip onto the top layer should trigger a visual "infiltration ripple" animation using Canvas `arc()` particles and dynamic opacity shifts.
- **Dynamic Physics/Vector Overlays**:
    - Draw a load vehicle (axle icon) moving across the pavement. 
    - Implement a real-time vector overlay showing the **Stress Distribution Cone**. As the vehicle moves, the cone must animate its depth and width based on the layer parameters assigned.
- **Graphing & Calculation**:
    - An integrated "Real-Time Response" graph showing pressure vs. depth. As layers are modified via drag-and-drop, the curve must redraw using `requestAnimationFrame` with an easing function.

### 3. PEDAGOGICAL MECHANICS
- **Gamified Codebook Reference**: Include a sidebar "IS Codebook" widget. When the student encounters a design parameter, they must click the "Open Codebook" icon, select the relevant clause, and drag a "Clause Reference Chip" into the main formula slot to "unlock" the next calculation phase.
- **Superposition Visualizer**: Show a split-screen view: Left side is the visual layer stack; Right side is the mathematical equation. As parameters change (e.g., changing subgrade CBR), the numerical inputs in the equation must pulse and update in real-time.

### 4. MULTIMEDIA & NARRATION
- **Web Audio Synth**: 
    - Successful placement/snap: Low-latency 440Hz sine wave "chime."
    - Error (invalid layer logic): 150Hz distorted "warning thrum."
    - Vehicle traversal: Subtle "rhythmic rumble" (low-pass filtered white noise).
- **Speech Synthesis**: Utilize `window.speechSynthesis`. Trigger an educational voiceover when a user drops a parameter (e.g., "Correct. High rainfall increases pore water pressure, necessitating improved subsurface drainage.")

### 5. TECHNICAL CONSTRAINTS
- **Canvas Rendering**: Use high-DPI scaling (backingStorePixelRatio). All lines must be drawn using `context.lineJoin = 'round'` for a professional schematic aesthetic.
- **Animations**: Use GSAP or standard Web API `requestAnimationFrame` for all transitions. Avoid choppy UI; use sub-pixel rendering.
- **Interaction**: Implement custom `dragstart`, `dragover`, and `drop` handlers. Provide visual feedback for drop targets (e.g., a green glowing border pulse when a draggable object enters a drop-zone radius).

### 6. DELIVERY FORMAT
- Provide the entire solution as a single-file prototype (HTML/CSS/JS).
- Ensure all logic is self-contained. 
- Use the "Cyber-Engineering" aesthetic: Translucent glass, cyan neon borders, and clean, modular typography.
