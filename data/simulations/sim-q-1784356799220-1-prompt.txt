**System Prompt for Interactive Engineering Simulation Generator:**

**Objective:** Develop a high-fidelity, interactive, browser-based pedagogical simulation for "Design of Slab Base Foundations" using HTML5, Canvas API, Tailwind CSS, and Web Audio/Speech APIs. The application must function as a "Playful Engineering Sandbox" for students.

### 1. Aesthetic & UI/UX Guidelines
*   **The Look:** "Cyber-Engineering Dark Mode." Use a deep charcoal background (#0f172a), translucent glass-morphism panels (backdrop-filter: blur(10px)), and vibrant neon accents (Cyan for structural lines, Magenta for force vectors, Lime for successful interactions).
*   **Responsiveness:** Use CSS Grid/Flexbox with 100vh containment. No scrolling allowed. Canvas must auto-resize to fit the viewport while maintaining high-DPI (Retina) clarity.
*   **Pedagogy:** Adopt an ELI5 (Explain Like I'm 5) personality. The app should feel like a toy—bouncy, responsive, and rewarding.

### 2. Core Interactive Features
*   **Gesture-Driven Controls:** Implement pointer/mouse tracking where sweeping the cursor horizontally "bends" or "stretches" structural members in the canvas with real-time elastic deformation physics.
*   **Real-Time Math Engine:** Create an internal state object for the problem variables (Load, Steel Grade, Soil Capacity). Changing a slider or dropping a value chip must trigger an immediate recalculation of the base plate area, displayed in a floating dynamic overlay.
*   **Gamified Drag-and-Drop:** 
    *   **Value Chips:** Create draggable "Numerical Chips" (e.g., "500 kN", "Fe 410", "M20") that users drag from a sidebar onto "Formula Target Slots" within the canvas.
    *   **Physics Feedback:** Upon correct placement, the target slot glows green with a satisfying "chime" sound (Web Audio Oscillator sequence). Incorrect placement triggers a red glow and a "boing" sound.
*   **Live Visualizations:**
    *   **Force Vector Overlay:** Dynamic arrows (magenta) that scale and move based on input loads.
    *   **Superposition Visualizer:** A stacked bar chart showing the breakdown of pressure distribution beneath the slab base.

### 3. Structural Design Specifics (IS 800:2007 Focus)
*   **Interactive Checklist:** A sidebar panel showing the design process (Step 1: Classification, Step 2: Load Assessment, Step 3: Base Plate Sizing). Transitions between steps must be animated with a "Success" pulse.
*   **Codal Reference Book:** Include an "IS 800 Codex" icon. When clicked, it renders a glass panel displaying the exact clause (e.g., Cl. 7.4.3) related to the current step. Dragging a clause onto the workspace "unlocks" the relevant design equation.
*   **Animation Sequences:**
    *   **Concrete Pour:** Use a canvas particle animation to show liquid concrete (M20) filling the volume around the footing as parameters are confirmed.
    *   **Steel Glow:** Rebar and base plate geometries should pulse with a neon internal glow when parameters are finalized, representing internal stress distribution.

### 4. Audio & Narration (ELI5 Style)
*   **Dynamic Audio Synth:** Map structural variables to Web Audio API oscillators. Increasing the "Load" slider should increase the pitch (frequency) of an ambient tone, providing a visceral "feeling" of increasing pressure.
*   **Speech Synthesis:** Integrate `window.speechSynthesis`. Trigger friendly, simplified narrations (e.g., "Whoa! That's a lot of weight! Let's make the base plate wider so the soil doesn't squish!") when users perform specific actions or hit design milestones.

### 5. Technical Implementation Requirements
*   **State Management:** Use a central state object to keep the diagram, formula slots, and active narration in sync.
*   **Canvas Layering:** Use an off-screen buffer approach for layering: 
    *   Layer 1: Engineering Grid/Background.
    *   Layer 2: Structural Geometry (Beam/Column/Base).
    *   Layer 3: Dynamic Force Vectors & Particles.
    *   Layer 4: UI/Labels/Glass Panels.
*   **High Performance:** Ensure all animations run at 60fps. Utilize `requestAnimationFrame` for all physical deformations.

### 6. Required Deliverable
Produce a single `index.html` file containing:
*   Embedded CSS (Tailwind via CDN).
*   The full simulation logic in a single `<script>` block.
*   No external dependencies other than standard libraries (Canvas, Web Audio, SpeechSynthesis).
*   **Zero exam paper text blocks.** The screen must be entirely dedicated to the simulation environment and interactive UI elements.
