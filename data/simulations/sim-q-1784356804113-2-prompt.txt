### Prompt for Gemini: Structural Engineering Simulation Generator

**Objective:** Create a high-fidelity, interactive, browser-based simulation using HTML5, CSS3, and Vanilla JavaScript to visualize the Limit State Design (LSD) of a Singly Reinforced RCC Beam.

**1. Visual Simulation Strategy:**
*   **Engine:** Use a dual-canvas approach. Canvas A (left) renders the Beam Cross-section (Rectangular, b x d) and the Strain/Stress distribution diagram (Parabolic-Rectangular). Canvas B (right) renders the real-time Force diagram (Compression C and Tension T vectors).
*   **Visual Logic:** The beam cross-section must update its scale dynamically based on input sliders. The Neutral Axis (x_u) should be a horizontal dashed line that moves vertically as sliders adjust. Stress blocks must animate their curvature and depth based on the balanced section logic.

**2. Interactive Elements & Inputs:**
*   **Control Panel (Glassmorphic Sidebar):** Include range sliders for:
    *   Width ($b$ in mm): 200–500
    *   Effective Depth ($d$ in mm): 300–800
    *   Concrete Grade ($f_{ck}$ in MPa): M20, M25, M30
    *   Steel Grade ($f_y$ in MPa): Fe415, Fe500
*   **Drag & Drop:** Allow the user to drag the neutral axis indicator line manually on the canvas to see the stress distribution change in real-time, with values updating in the text dashboard.
*   **Live Metrics:** Display $x_{u,max}$, Lever Arm ($z = d - 0.42x_u$), Total Compression ($C = 0.36 f_{ck} b x_u$), and Tension ($T = 0.87 f_y A_{st}$) in a dashboard that updates on every slider move.

**3. Sound Design (Web Audio API):**
*   Implement a `SynthController` class. 
*   **Beeps:** Trigger a low-frequency oscillator (sine wave, 200Hz) when sliders are moved.
*   **Confirmation:** Trigger a "success" sweep (oscillator frequency shift from 400Hz to 800Hz) when the beam hits a "balanced" state (where $x_u = x_{u,max}$). 
*   **Action Cues:** Use `GainNode` to ensure smooth audio fades (no clicking).

**4. Narrative Text-to-Speech (TTS):**
*   Integrate a "Tutorial Mode" button. When active, use `window.speechSynthesis`.
*   As the user adjusts a parameter, trigger an explanation: "Increasing the effective depth shifts the neutral axis downwards, increasing the lever arm length."
*   Provide a "Explain Current State" button that reads the active formula calculation: "Total compression is currently calculated as 0.36 times f-c-k times b times x-u."

**5. Diagram Animations & Math Rendering:**
*   Use `requestAnimationFrame` for fluid movement.
*   Render math formulas using a clean, overlay-text approach (or simulated SVG paths). Vectors ($C$ and $T$) should be represented as arrows that scale in length and change color (e.g., Cool Blue for Tension, Hot Orange for Compression) based on magnitude.
*   Ensure the stress diagram overlays the cross-section with 40% opacity glass-like fills.

**6. Aesthetics & UI:**
*   **Dark Mode:** Background color: `#0f172a`.
*   **Accents:** Glowing neon cyan for vectors, neon orange for the neutral axis, and crisp white for UI borders.
*   **Typography:** Sans-serif (Inter or Roboto).
*   **Styling:** Use `backdrop-filter: blur(10px)` for the control panel. Use CSS transitions for all hover states and slider movements.

**Technical Constraints:**
*   Do not use external libraries (D3, jQuery, etc.). Use pure Vanilla JS.
*   Ensure the code is modular (CSS in `<style>`, JS in `<script>`).
*   The simulation must be fully responsive.
*   Include a "Reset" button to return all values to the default M20/Fe415 state. 

**Deliverable Requirements:**
*   Provide a single-file HTML solution.
*   Ensure all calculation formulas strictly follow the IS 456:2000 Limit State Design methodology for singly reinforced sections.
