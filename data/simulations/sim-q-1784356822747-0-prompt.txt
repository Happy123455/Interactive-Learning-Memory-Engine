Act as an expert educational software developer. Build a sophisticated, single-file HTML5 simulation for a college-level course on "Design of RC Beams Subjected to Combined Bending and Torsion." The interface must be a modern, dark-themed dashboard with glassmorphic UI elements and neon accents, providing an interactive, immersive learning environment.

### 1. Visual Simulation Strategy
*   **Central Canvas**: Use a 2D HTML5 Canvas to render a 3D-perspective concrete beam.
*   **Dynamic Reinforcement**: Visualize longitudinal bars and closed-loop stirrups. When inputs change, the stirrups should dynamically resize/thicken.
*   **Vector Overlays**: Use vector arrows to represent the Bending Moment ($M_u$) and Torsional Moment ($T_u$) acting on the beam cross-section. These vectors must scale in real-time as users modify slider inputs.
*   **Real-time Graphing**: Implement an integrated chart (using a simple custom draw loop) that displays the interaction curve of $M$ vs $T$, showing the "Current State" point moving on the curve as values change.

### 2. Interactive Elements
*   **Drag-and-Drop Interaction**: Allow users to "drag" an external load point along the beam span to see how the local $M$ and $T$ values update.
*   **Control Panel**: Include a glassmorphic sidebar with sliders for:
    *   `Bending Moment (Mu)`
    *   `Torsional Moment (Tu)`
    *   `Concrete Grade (fck)`
    *   `Beam Width/Depth`
*   **Live Equations**: An "Equation Overlay" box that renders the Equivalent Bending Moment ($M_{e} = M_u + T_u(1 + D/b)/1.7$) using dynamic text that updates the math as inputs shift.

### 3. Web Audio API Sound Design
*   **Implementation**: Use the Web Audio API (`AudioContext`, `OscillatorNode`, `GainNode`) for native synthesis.
*   **Trigger Events**: 
    *   **Slider Movement**: Subtle, low-pass filtered sine-wave "click" or "thrum" for every incremental slider change.
    *   **Boundary Reached**: A sharp, higher-frequency pulse when a design parameter exceeds safe limits (Structural Failure/Warning).
    *   **Calculation Success**: A gentle, ascending "chord" generated by layering three oscillators (Sine, Triangle) when a safe reinforcement design is calculated.

### 4. Narrative Text-to-Speech (TTS)
*   **Narrate Button**: Add a "Virtual Professor" button that triggers `window.speechSynthesis`.
*   **Behavior**: When active, it should narrate the design procedure step-by-step: "First, we determine the equivalent bending moment. Notice how the stirrup density increases as we increase the Torsional force slider."
*   **Auto-Triggering**: Provide an option to toggle "Guided Tour" mode, where the app speaks as the user interacts with specific controls.

### 5. Diagram Animations & Aesthetics
*   **Transitions**: Use `requestAnimationFrame` for smooth interpolation of all vector arrows and reinforcement bar resizing.
*   **Style**: 
    *   **Theme**: Deep charcoal background (#121212) with neon cyan/magenta accents.
    *   **Elements**: Glassmorphic panels with `backdrop-filter: blur(10px)`.
    *   **Typography**: Clean sans-serif (Inter or Roboto).
    *   **Effects**: Subtle glow animations on active interaction nodes.

### 6. Code Architecture Requirements
*   **Single File**: Provide all HTML, CSS, and JS within one block.
*   **Responsive**: The canvas should resize appropriately for different screen widths.
*   **Clean Code**: Modularize logic for "Physics/Calculation," "AudioEngine," "VisualRenderer," and "Narrator."

**Technical Challenge**: Ensure the interaction between the beam's visual "stress state" (color shifting from cyan to orange to red as torsion increases) remains perfectly synced with the real-time interaction formula calculations.
