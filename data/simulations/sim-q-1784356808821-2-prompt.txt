Act as an expert Educational Software Developer and Prompt Engineer. Your objective is to create a high-fidelity, interactive, web-based simulation for a "Doubly Reinforced RCC Beam Design" tool. This tool will serve as a teaching aid for an "Elementary Structural Design" course.

**1. Technical Architecture & Aesthetics**
*   **Theme:** Use a "Cyber-Engineering" aesthetic: dark charcoal background (#121212), glowing neon cyan/amber accents, glassmorphic UI panels (backdrop-filter: blur), and clean Inter or Montserrat sans-serif typography.
*   **Canvas Framework:** Use a 2D Canvas API for the beam rendering and force diagram overlays. Use Chart.js or D3.js for real-time graphing of the Stress-Strain distribution.
*   **Responsive Layout:** Sidebar for inputs/equations, main central area for the dynamic 2D Beam visualization.

**2. Simulation & Visual Strategy**
*   **The Beam:** Render a 2D cross-section of the 250mm x 600mm beam. Show "live" cross-hatching for concrete and distinct colored circles for Tension Steel (bottom) and Compression Steel (top).
*   **Interactive Draggable Elements:** Allow users to drag the position of steel bars vertically (adjusting effective depth $d$ and $d'$). As the bars move, update the effective depth values in real-time.
*   **Vector Overlays:** Display dynamic force vectors showing the Neutral Axis (NA). As the user modifies the Moment ($M$) or the concrete grade via sliders, animate the NA shifting up or down with a smooth transition.
*   **Equation Plotting:** Create an adjacent graph window showing the Stress-Strain profile (Parabolic-Rectangular stress block). Animate the block’s compression zone height ($x_u$) as parameters change.

**3. Interaction & Controls**
*   **Input Sliders:** Provide precise controls for:
    *   Bending Moment ($M$) in kNm.
    *   Concrete Grade ($f_{ck}$ in MPa).
    *   Steel Grade ($f_y$ in MPa).
*   **Dynamic Labels:** All calculation outputs (Area of steel $A_{st}$, $A_{sc}$) must be linked to the variables; as sliders move, the variables must update instantly using the Limit State Design formulas.
*   **Equation HUD:** Display the current calculation steps on the screen using MathJax or formatted LaTeX, highlighting the specific line currently being solved by the inputs.

**4. Web Audio API (Native Synthesis)**
*   **Mechanism:** Create a `SynthEngine` class using the Web Audio API. 
*   **Audio Triggers:**
    *   **Drag Interaction:** A subtle, low-pass filtered "thrum" sound when dragging reinforcement.
    *   **Threshold Alerts:** An oscillator sweep (sine to triangle) when the beam reaches a "balanced" or "over-reinforced" state.
    *   **Update Tick:** A short, high-frequency "click" (short envelope, gain node fade out) when slider values change. 
    *   *Constraint:* Do not use external files; synthesize all sounds using `OscillatorNode` and `GainNode`.

**5. Narrative Text-to-Speech (TTS)**
*   **Functionality:** Implement a "Narrate" button that triggers `window.speechSynthesis`.
*   **Logic:** Create a `Narrator` module that maps the current UI state to descriptive text. Example: "Adjusting the effective depth increases the lever arm, significantly reducing the required steel area."
*   **Auto-Trigger:** Include an "Explain Step" button that, when clicked, pauses the simulation and narrates the current engineering principle being applied (e.g., "The compression steel is now helping to resist the internal couple").

**6. Implementation Guidelines for the Model**
*   **Coding Standards:** Use modern ES6+, modular JavaScript, and CSS variables for theme management.
*   **Smoothness:** Use `requestAnimationFrame` for all diagram movements to ensure 60FPS fluid motion.
*   **Code Structure:**
    *   `UIModule`: Manages glassmorphic panels and sliders.
    *   `PhysicsEngine`: Calculates $A_{st}$ and $A_{sc}$ based on IS 456 (or general LSD) standards.
    *   `Visualizer`: Handles the canvas drawing loop.
    *   `AudioEngine`: Manages Web Audio API nodes.
    *   `Narrator`: Manages `SpeechSynthesisUtterance` queues.

**7. Expected Output:**
Provide the complete HTML/CSS/JS file (single-file approach) that renders the dashboard, links the inputs to the calculations, provides the synthesized audio cues, and includes the narrator logic as requested. Ensure the code is heavily commented to explain the calculation logic used for the Doubly Reinforced Beam design.
